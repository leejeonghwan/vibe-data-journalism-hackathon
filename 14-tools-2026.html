도구는 흐름대로, 판단은 사람이

발굴에서 교열까지, 지금 바로 쓸 수 있는 도구를 취재 흐름 순으로 정리한다.

도구는 매년 바뀌지만 흐름은 바뀌지 않는다 — 발굴 → 수집 → 문서처리 → 분석 → 전사 → 검증 → 교열. 각 단계에서 AI와 오픈소스가 사람의 손을 몇 배로 늘려 준다. 늘어나는 건 손이지 판단이 아니다. 증강(augmentation)이지 자동화(automation)가 아니다.

쓰기 전에
아래 상당수는 가격·무료한도·기자 자격 조건이 자주 바뀐다. 쓰기 전 공식 사이트에서 상태·라이선스를 확인할 것. 민감 자료는 외부 전송 없는 로컬 도구를 우선한다.

취재 도구 — 흐름별

단계마다 '무엇을 위한 도구인지'부터 본다.

1. 발굴 · OSINT

  • Bellingcat Toolkit — 지오로케이션·소셜·검증 수백 개 도구 큐레이션 + 오픈소스 CLI(ShadowFinder·auto-archiver). github.com/bellingcat
  • Buried Signals (Spotlight/Mycroft) — 기자용 OSINT 조사 오케스트레이터(구조화 브리프·출처 명기·독립 팩트체크). 일부 로컬 구동.
  • OpenSanctions — 국제 제재·정치적 주요 인물(PEP) 공개 DB. 이름 교차 대조.
  • Aleph / OpenAleph (OCCRP) — 유출문서·엔티티를 올려 검색·연결. 자체 호스팅 가능.

2. 수집 · 크롤링

  • BeautifulSoup · Scrapy · Playwright — 파이썬 크롤링 표준(정적·동적). 4강에서 다룬 그 흐름.
  • Simplescraper · dataminer — 코딩 없이 브라우저 확장으로 표·목록 수집.
  • 공공 API가 먼저 — 국토부 실거래가·심평원·DART·나라장터·선관위·data.go.kr은 크롤링보다 API.

3. 대량 문서 처리 · OCR

  • Google Pinpoint — 수십만 건 문서·필기·오디오 OCR·전사·엔티티 추출 후 검색. 인증 기자 무료.
  • DocumentCloud — 1차 문서 호스팅·OCR·전문검색·주석·기사 임베드. 인증 기자 무료.
  • Docling (IBM) — PDF·오피스·이미지를 표까지 살려 Markdown/JSON으로. 오프라인.
  • Tabula · pdfplumber · PaddleOCR — 표 추출·폼 파싱·스캔 OCR.
  • NotebookLM — 한정 문서셋에 질문(RAG식). 요약은 강하나 정확한 원문 인용은 약함 — 검증은 사람이.

4. 데이터 정제 · 분석 · 시각화

  • OpenRefine — 지저분한 데이터 정제·클러스터링 파워툴(엔티티 매칭에 필수).
  • Datasette — CSV/SQLite를 즉시 탐색·공개 API·웹앱으로. 깃허브 페이지 배포 궁합.
  • pandas · csvkit · QGIS — 파이썬·CLI 분석, 지리공간은 QGIS.

5. 전사 · 인터뷰

  • Whisper (로컬) — 무료·오프라인 전사. 민감 인터뷰에 권장.
  • Otter · Good Tape · Descript — 실시간·화자 분리·편집. 무료한도·정확도는 제각각.
  • 요약이 아니라 정확한 워딩이 목적이면 전사 → 화자매칭 → 핵심발언 인용으로 쪼갠다.

6. 검증 · 팩트체크

  • InVID & WeVerify — 영상·이미지 검증 브라우저 툴킷(키프레임·역검색·메타데이터).
  • ExifTool(로컬) · 역이미지(Google·TinEye·Yandex) — 메타데이터·출처 추적.
  • SunCalc · Bellingcat Shadow Finder — 그림자로 시각·위치 추정. Google Fact Check Explorer — 클레임 매칭. C2PA — 출처·진위.
  • 한국: SNU팩트체크 · 빅카인즈(BigKinds) — 기사 코퍼스 검색·인용 대조.

7. 교열 · 맞춤법

  • 바른한글(구 부산대 맞춤법 검사기) — 문맥 교정·띄어쓰기·외래어. 국내 표준격.
  • 바른AI — 교정 사유·어문규정 근거 표기, 사용자 사전·API(대량 교열).
  • 국립국어원 — 어문 규범·표준국어대사전. 교정 '근거'의 1차 출처.

8. 바로 끌어 쓰는 깃허브

  • awesome-datajournalism · awesome-journalism — 워크플로별 도구 큐레이션의 출발점.
  • jamditis/claude-skills-journalism — Claude Code용 저널리즘 스킬(검증·FOIA·데이터저널리즘). 커뮤니티 프로젝트.

해커톤 과제 10 — 큰 방향을 던진다

아래 10개 트랙 중 하나를 골라 3시간 안에 결과물 하나를 완성한다. 과제는 정답이 아니라 출발 질문이다.

공통 규격 — 어느 트랙이든 동일
낼 것(하나로 완결되게): ① 공개 대시보드(단일 HTML, 깃허브 페이지 배포) · ② 기사 리드 3단락 + 넛그래프("이게 왜 중요한가") · ③ 팩트시트(숫자·출처·방법·한계 한 장) · ④ 데이터 탐색기 — 중 하나 이상.
평가 4축(각 25점): 질문 · 방법(재현 가능·상관≠인과) · 결과물(직관·완결) · 정직성(출처·기준일·한계).
넘지 말 것: 숫자는 최소 1건 원본 대조 / 추정은 추정이라 표기 / 민감 자료는 로컬로 / AI가 쓴 문장도 책임은 사람이.
1

공개 데이터 한 개, 신호 하나

흔한 공개 데이터에서 "이건 좀 이상한데?" 하나를 찾아낸다. 분포를 그려 튀는 값 1개를 특정. 함정: 데이터 전체를 설명하려 들기. (LH·13강 축소판)

2

두 데이터를 연결하라

따로 보면 평범한 두 자료를 이름·법인·주소로 엔티티 매칭. 동명이인은 2차 식별자로 거른다. 함정: 이름만 같은 걸 같은 사람으로 단정. (수주왕·10강)

3

문서 더미에서 패턴

공개 문서 수백~수천 장을 DocumentCloud/Pinpoint에 올려 OCR·검색·빈도. 함정: 요약 AI를 그대로 믿기 — 인용은 원문 페이지로 확인.

4

돈의 흐름 지도

국고보조금·정치자금·공공기관 집행내역의 출처→수혜자 흐름을 집계·시각화. 함정: 큰 금액=문제로 단정. 용도·전년 대비를 함께.

5

시간을 되감기

지분·가격·인사 등 시점 있는 데이터로 연도 스크러버 타임라인. 함정: 디자인에 숫자가 가려지기 — 각 시점 값은 원문 대조. (현대차 방식)

6

지도 위의 질문

주소·좌표 데이터를 지오코딩해 밀집·격차·공백을 본다(QGIS/웹지도). 함정: 인구·면적 보정 없이 '많다/적다'. (12강 선거 지도)

7

가설을 검증하라 (팩트체크)

떠도는 수치 주장 1개를 반증 가능한 질문으로 쪼개 공개 데이터로 대조. 함정: 결론 정해놓고 데이터 고르기 — 반론도 같이.

8

말의 기록

공개 회의·국회·회견 녹취를 Whisper 전사 → 화자 매칭 → 주제별 재구성. 함정: 가공된 인용 — 따옴표 안은 실제 워딩만.

9

이미지·영상 검증 (OSINT)

출처 불명 사진/영상 1건의 위치·시각을 역이미지·메타데이터·그림자로 특정. 함정: 한 단서로 단정 — 최소 2개 독립 단서 교차.

10

나만의 추적기

한 번 쓰고 끝이 아니라 계속 갱신되는 지표(공약 이행·예산 집행). 판정 규칙을 미리 공개. 함정: 기준 모호한 '달성/미달'.

고르기 힘들면
코딩 처음이면 1·7(공개 통계 하나로 완결), 데이터 좀 다뤄봤으면 2·4·5, 취재·인터뷰가 강점이면 8·9, 계속 쓸 걸 만들고 싶으면 10. 트랙은 울타리가 아니라 사다리다 — 작게 시작해 하나만 끝까지 완성하는 팀이 이긴다.

하루 실습 스타터 키트

코딩 입문 기자가 하루에 한 바퀴 돌아보는 최소 코스.

1

공개 데이터 1개 고르기

data.go.kr · 실거래가 · 심평원 · DART 중 딱 하나.

2

수집·정제

Requests+BeautifulSoup(또는 API) → OpenRefine로 정리.

3

문서가 많으면

DocumentCloud/Pinpoint에 올려 OCR·검색. 스캔은 PaddleOCR.

4

분석·공개

Datasette로 탐색 → 단일 HTML 대시보드 → GitHub Pages 배포(6강 방식).

5

검증

이미지/영상은 InVID, 위치는 SunCalc/Shadow Finder, 숫자는 원본 1건 직접 대조.

6

교열

바른한글/바른AI로 1차, 국립국어원으로 근거 확인.

실습 과제

  1. 위 해커톤 과제 10 중 하나를 고른다. 어울리는 사례 축소판을 하나 떠올린다(예: 트랙2 → 수주왕 축소판).
  2. 흐름별 도구 중 이 과제에 필요한 것을 3개 이내로 고른다(수집·분석·검증 각 1개면 충분).
  3. 3시간 타임박스로 결과물 하나를 만든다 — 대시보드/리드+넛그래프/팩트시트 중 하나.
  4. 숫자 1건을 원본과 직접 대조하고, 팩트시트에 출처·기준일·한계를 적는다.
  5. 깃허브 페이지로 배포하고, "이게 왜 중요한가"를 한 문단으로 닫는다.
